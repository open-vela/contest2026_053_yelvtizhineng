# 植小伴 · AI 智能养植伴侣

> **2026 首届 openvela AI 硬件开发者大赛** 参赛作品
> 队伍：**叶绿体智能**（北京见壤智能科技有限公司）
> 固件版本：**V1.3.0**　|　平台：**openvela（NuttX 内核）** + ESP32-S3

植小伴把智能养植从"只测不管"推进到 **感知 → 诊断 → 执行 → 陪伴** 的完整闭环：
一块触摸屏板卡采集土壤八参数与叶片图像，语音直接问 AI，云端大模型给出诊断与养护方案，
手机端随时查看，养死了还能凭传感器数据一键理赔。

## 三、快速开始

### 3.1 云平台（**不需要硬件，5 分钟跑起来**）

评审同学如果手边没有板卡，直接从这一节开始即可，全部功能都能在浏览器里看到。

```bash
cd server/plant_server
pip install -r requirements.txt
python -m app.services.service_ctl --start --port 8011
# 或者：python run_server.py --port 8011
```

启动后：

| 入口 | 地址 | 说明 |
|------|------|------|
| 网页管理台 | `http://127.0.0.1:8011/admin/` | 服务器状态、设备、用户、理赔管控（口令由环境变量 `PLANT_ADMIN_PASSWORD` 设置） |
| 手机端 | `http://127.0.0.1:8011/mobile/` | 手机浏览器打开即用，可"添加到主屏幕" |
| 接口文档 | `http://127.0.0.1:8011/docs` | Swagger，89 个路径可直接试 |

**未配置大模型密钥时会自动进入 mock 演示模式**（打印 `[AI] 演示模式（mock）`），
服务不会崩，界面流程全部可走通。

要接真实大模型（小米 MiMo），设置环境变量后再启动：

```bash
export PLANT_MIMO_KEY=<你的密钥>     # 必填，缺失即进入 mock
export PLANT_AI_MODE=auto            # 或 mimo=强制真实 / mock=强制演示
export PLANT_MIMO_MODEL=mimo-v2.5            # 多模态主模型（看图 / 听音）
export PLANT_MIMO_TEXT_MODEL=mimo-v2.5-pro   # 纯文本模型
export PLANT_MIMO_ASR_MODEL=mimo-v2.5-asr    # 语音转写
export PLANT_TTS_MODEL=mimo-v2.5-tts         # 语音合成
```

**登录演示账号很方便**：默认开启了演示模式（`PLANT_DEMO_OPEN=1`），
短信验证码固定为 **`123456`**，也可用"一键演示登录"直接进。

详见 `docs/04_云平台运行与部署.md`。

### 3.2 嵌入式端（需要 ESP32-S3 硬件）

固件建在 openvela / NuttX 之上，需要先准备上游平台代码，再套用本仓库的补丁。

**最省事的方式**：直接烧 `firmware/prebuilt/nuttx_v1.3.0.bin`（已编译好，就是真机跑的那一版）。

```bash
python -m esptool --chip esp32s3 --port <串口> --baud 921600 \
  --before default-reset --after hard-reset write-flash \
  --flash-mode dio --flash-freq 80m --flash-size 16MB \
  0x10000 firmware/prebuilt/nuttx_v1.3.0.bin
```

> ⚠️ **只写 `0x10000`**。禁止 `erase_flash`，禁止写 `0x0` —— 会擦掉 OTA 数据与设备配置。

**从源码编译**的完整步骤（含上游拉取、补丁套用、编译、烧录、配网）见
`docs/03_固件编译与烧录.md`，硬件接线见 `docs/02_硬件与接线.md`。

### 3.3 手机端

两个形态、一套界面：

| 形态 | 怎么用 |
|------|--------|
| PWA（推荐先试这个） | 手机浏览器打开 `http://<服务器IP>:8011/mobile/`，可"添加到主屏幕"当 App 用，**不需要安装** |
| 安卓 APK | 安装 `mobile/plant_android/build/ZhiXiaoBan.apk`（包名 `com.zhixiaoban.app`） |

> 手机端界面本体在服务器上（`server/plant_server/app/static/mobile/`），
> 所以改界面不用重新发 APK；只有改"壳"（权限、原生拍照、原生录音）才需要重新编译。
> 重新编译步骤见 `docs/05_手机端构建.md`。

## 四、硬件

| 项 | 型号 / 规格 |
|----|-----------|
| 主控开发板 | **CHD-ESP32-S3-Box**（ESP32-S3，16 MB Flash，板载触摸屏 + 摄像头接口 + 双 codec + SD 卡槽） |
| 土壤传感器 | **RS485 八合一土壤传感器**，Modbus RTU，9600 8N1，从站地址 `0x02`，接 UART0 |
| 摄像头 | OV3660（DVP） |
| 音频 | 采集 ES7210（麦克风阵列）+ 播放 ES8311 |
| 显示 | ST7796 LCD + 触摸 |
| 存储 | microSD（配置持久化在 `/mnt/sd/plant.cfg`） |
| 电源 | 锂电池（电量按 3.3 V≈满电、3.7 V 上限标定） |

**关键设计**：摄像头 DVP 的 `IO42/IO40` 与土壤传感器的 `UART0` **复用同一组引脚**，
两条数据流不能同时占用 —— 本作品用"进拍照页停轮询 + 关摄像头 + `esp32s3_uart0_reclaim_pins()` 回收引脚"的互斥序列解决。

接线表见 `docs/02_硬件与接线.md`。

## 七、openvela 能力落地与上游贡献

模板要求"至少落地图形 / AI / 多媒体三项核心能力之一"，本作品**三项均落地**：

| 能力 | 落地内容 |
|------|---------|
| 图形 | LVGL v9 九屏中文交互界面 + 自造中文（12/16/19/25 四档）与 emoji（16/20/24/32）字库 |
| AI | 云端 MiMo 四类能力 + 端侧阈值规则；语音 / 图像 / 文本三通道 |
| 多媒体 | ES7210 录音、ES8311 播放、WAV 流式解析与重采样、OV3660 取帧 |

**对 openvela / NuttX 的优化与拓展（3 处）**

1. `drivers/serial/serial.c`：控制台输出由**无限等待改为限时等待 200 ms + 超时丢弃积压**
   —— 解决"上位机开着串口不读数据就把板卡拖卡住"的问题。
2. `arch/xtensa/src/esp32s3/`：新增 **`esp32s3_uart0_reclaim_pins()`**，
   让摄像头 DVP 释放后能把 `IO42/IO40` 交还给 UART0 —— 这是"摄像头 + RS485 传感器共存"的关键补丁。
3. `hal_i2s.c`：新增 **`hal_i2s_write_async()`**，支撑语音回复的"边下边播"。

## 九、已知限制

1. 板卡**只支持 2.4G Wi-Fi**，5G 频段连不上。
2. 板卡控制台走芯片内置 USB 串口，**打开串口却不读数据会拖住板卡输出**（已做限时等待缓解）。
3. **继电器尚未接入**：执行环节是"板卡上点一下图标即完成"的干跑形态，
   服务器下发 → 板卡取单 → 回执整条链路已跑通，接上真实继电器沿用同一套接口即可。
4. 语音对话目前是**按按钮说话**，未做唤醒词。
5. 曾出现一次堆断言崩溃 `mm_heap/mm_malloc.c:236`（相机/语音页连续操作约 2 分钟），
   板卡自愈重启后未复现，持续观察中。
