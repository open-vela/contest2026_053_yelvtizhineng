# 最终提交压缩包 · 打包说明

> 模板原文：**"将上表材料打包为一个压缩包，在大赛官网上传。压缩包命名格式为 `<队伍名称>-<作品名称>-<仓库名称>.zip`"**
> 示例：`不会嵌软-VelaSense-contest2026_042_buhuiqianruan.zip`

---

## 一、我们的压缩包名

```
叶绿体智能-植小伴-<仓库名称>.zip
```

`<仓库名称>` 必须与 GitHub 上赛事分配的专属仓名字**完全一致**。

- 如果仓库名是 `contest2026_042_叶绿体智能` → 包名就是 `叶绿体智能-植小伴-contest2026_042_叶绿体智能.zip`
- 仓库名待确认（见 `00_提交要求与清单\README_提交清单与进度.md` 第四节阻塞项 #1）

## 二、压缩包内部结构（建议）

```
叶绿体智能-植小伴-<仓库名称>/
├── 00_材料清单.md                 ← 一页说明：交了哪几件、对应文件名、联系方式
├── 01_技术报告/
│   └── 植小伴_技术报告_V1.0.pdf    ← 必交（也可同时放 .docx）
├── 02_演示视频/
│   └── 植小伴_演示视频.mp4         ← 必交，≤5 分钟
├── 03_作品展示照片/
│   ├── 01_前视图.jpg
│   ├── 02_后视图.jpg
│   ├── 03_侧视图.jpg
│   ├── 04_俯视图.jpg
│   ├── 05_接线特写.jpg
│   ├── 06_上电运行.jpg
│   └── 07_软件界面截图/            ← 可选，加分

    └── 植小伴_答辩PPT.pptx
```

## 三、三类东西**不要**放进压缩包

| 不要放 | 原因 |
|--------|------|
| 项目源码 | 模板明确"源码与 AI Coding 日志均在专属仓内，无需放入压缩包"，评审直接 clone 仓库 |
| AI Coding 日志（`logs/`） | 同上，且在仓库里，**不得手动删改** |
| 编译中间产物、`.git`、`node_modules`、`__pycache__` | 体积大、无意义 |

## 四、打包前的自查清单

- [ ] 压缩包名是**三段式**，且仓库名与 GitHub 实际仓名一字不差（注意中英文下划线与大小写）
- [ ] 技术报告是 **PDF 或 DOCX**（Markdown 原稿不算），章节与模板第二节对齐
- [ ] 技术报告里没有 `【待补】/【待确认】` 之类的占位标记
- [ ] 演示视频**时长 ≤5 分钟**（卡 4 分 50 秒更稳），含功能演示 + 交互操作 + AI 能力展示
- [ ] 硬件实物照片：前 / 后 / 侧 / 俯 四视图齐全，是实拍不是渲染
- [ ] 海报与 PPT 若要做，导出为 `.pdf` / `.jpg` / `.pptx`
- [ ] 解压后目录能正常打开，中文文件名不乱码（建议用 UTF-8 或 zip 而非 rar）
- [ ] 视频大小：官网一般有上传上限，**导出 1080p / 8~12 Mbps** 通常 100~300 MB，若被限制再降到 720p
- [ ] 最后再确认一次：**专属仓里的代码能 clone 下来直接编译通过**

## 五、打包命令（Windows PowerShell）

```powershell
$src = "E:\zhixiaoban_prj\_大赛提交\openvela2026_叶绿体智能_植小伴\_待打包\叶绿体智能-植小伴-<仓库名称>"
$dst = "E:\zhixiaoban_prj\_大赛提交\openvela2026_叶绿体智能_植小伴\06_提交压缩包\叶绿体智能-植小伴-<仓库名称>.zip"
Compress-Archive -Path $src -DestinationPath $dst -CompressionLevel Optimal
```

> 建议先在 `06_提交压缩包\` 下建一个 `_待打包\` 子目录，
> 按第二节的结构把文件摆好、肉眼检查一遍，再整目录压缩，避免漏文件或带上临时文件。
