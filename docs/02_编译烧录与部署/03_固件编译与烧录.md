# 03 · 固件编译与烧录

> 目标硬件：CHD-ESP32-S3-Box（ESP32-S3）
> 平台：**openvela（NuttX 内核）** + nuttx-apps + vendor/espressif
> 产出：`nuttx.bin`（烧到 `0x10000`）+ `partition-table-2mb-ab.bin`（烧到 `0x8000`）
>
> ⚠️ **两个都得烧**。只烧 `nuttx.bin` 的板子会踩"OTA 升级成功但版本没变"的坑
> —— 详见 `firmware/apps/plant-companion/docs/PARTITION_TABLE_HANDOVER.md`。

---

## 一、两种路径，先选一种

| 路径 | 适合谁 | 耗时 |
|------|-------|------|
| **A. 直接烧预编译固件** | 只想看效果、手边没有 Linux 编译环境 | 5 分钟 |
| **B. 从源码编译** | 要审代码、要改、要复现 | 30~60 分钟（首次拉上游代码较久） |

---

## 二、路径 A：直接烧预编译固件

仓库里已带**真机在跑的那一版**：

```
firmware/prebuilt/nuttx_v1.3.0.bin      1,827,008 字节
```

```bash
python -m esptool --chip esp32s3 --port COM3 --baud 921600 \
  --before default-reset --after hard-reset write-flash \
  --flash-mode dio --flash-freq 80m --flash-size 16MB \
  0x8000  firmware/partition/partition-table-2mb-ab.bin \
  0x10000 firmware/prebuilt/nuttx_v1.3.0.bin
```

> ⚠️ **只写 `0x8000`（分区表）与 `0x10000`（应用）这两段**。
> **禁止 `erase_flash`，禁止写 `0x0`** ——
> `0x0` 是引导程序，擦掉或写错会直接变砖；`erase_flash` 还会清掉
> OTA 数据与设备配置，板卡会回到"从未配过网"的状态。
> 需要 esptool 时：`pip install esptool`。

> ⚠️ **换板 / 首次烧录请连 `0x8000` 的分区表一起烧**（上面命令已包含）。
> 板卡如果留着旧分区表（`ota_1 @0x610000`），OTA 会出现
> "下载成功、SHA256 校验通过、切槽也写了，但重启后版本没变"。
> 排查与修复步骤见 `firmware/partition/README.md`。

烧完板卡自动重启，屏幕出现 `=== Firmware V1.3.0 ===` 即成功。

## 三、路径 B：从源码编译

### 3.1 环境要求

| 项 | 要求 |
|----|------|
| 系统 | Linux（推荐 Ubuntu 20.04/22.04）；Windows 需 WSL |
| 工具链 | Xtensa ESP32-S3 工具链（openvela prebuilts 自带） |
| Python | 3.8+，并安装 openvela 自带的 `kconfiglib` |
| 磁盘 | 建议预留 20 GB（上游三仓库 + 编译产物） |
| 其它 | `make`、`git`、`repo` 工具 |

### 3.2 拉取上游代码

本作品的基线是 **2026-09-03 的快照**：

| 仓库 | 基线 commit |
|------|------------|
| nuttx | `fc3f07c0871f4bdaca0d19e48bd9d8b45fe2314b` |
| apps | `bf70c804de0de6ed18dcd2eaf25d504ff2aabc89` |
| vendor/espressif | 无本地改动（沿用上游） |

**方式一：用 openvela 的 repo 工具（推荐）**

```bash
mkdir openvela && cd openvela
repo init -u https://github.com/open-vela/manifests.git -b dev-ai-contest-2026
repo sync -c -j8
```

**方式二：分别 clone 三个仓库**

```bash
git clone https://github.com/open-vela/nuttx.git            nuttx
git clone https://github.com/open-vela/nuttx-apps.git       apps
git clone https://github.com/open-vela/vendor_espressif.git vendor/espressif
```

> 说明：本作品开发期用的是 Gitee 镜像分支（`nuttx` / `nuttx-apps` / `vendor_espressif` 的
> `plant-companion-dev` 分支）。补丁是按上面的 commit 生成的，
> **套用在新版上游上可能有 fuzz 或偏移**，遇到冲突按上下文手工合入即可。

### 3.3 套用补丁

`firmware/patches/` 里是两个仓库相对基线的完整补丁：

| 文件 | 内容 |
|------|------|
| `nuttx_changes.diff` | 平台侧：17 个文件修改 + 8 个新增（约 454 KB） |
| `apps_changes.diff` | 应用侧：53 个修改 + 11 个新增 + 2 个删除（约 1.9 MB） |
| `nuttx_dot_config` | 板上实际生效的 `.config`（编译配置真相） |
| `board_defconfig_openvela` | 板级 defconfig |
| `基线版本.txt` | 两个仓库的 commit 与导出时间 |

```bash
# nuttx 侧
cd nuttx
git apply --stat ../firmware/patches/nuttx_changes.diff   # 先看会改哪些文件
git apply ../firmware/patches/nuttx_changes.diff

# apps 侧
cd ../apps
git apply ../firmware/patches/apps_changes.diff
```

### 3.4 放入应用源码

应用本体在 `firmware/apps/plant-companion/`，直接拷进 apps 仓库：

```bash
cp -r ../firmware/apps/plant-companion <apps>/apps/plant-companion
```

`apps_changes.diff` 里已经包含 `apps/Kconfig` 与 `apps/Make.defs` 的注册改动，
所以拷进去之后应用会被自动识别。

### 3.5 配置板级

板级配置目录：`nuttx/boards/xtensa/esp32s3/esp32s3-box/configs/openvela/`

```bash
cd nuttx
./tools/configure.sh esp32s3-box:openvela
```

> 若该配置目录不存在（补丁未含），把 `firmware/patches/board_defconfig_openvela`
> 复制进去并命名为 `defconfig` 即可。
> 需要核对最终配置时，与 `firmware/patches/nuttx_dot_config` 对比。
>
> 关键配置项：`CONFIG_ARCH_BOARD_ESP32S3_BOX=y`、`CONFIG_ESP32S3_CAM_DVP=y`、
> `CONFIG_ESP32S3_SDMMC=y`、`CONFIG_ESP32S3_I2S0=y`、`CONFIG_ESP32S3_SPIRAM=y`（Octal / 80 MHz）、
> `CONFIG_ESP32S3_UART0_TXPIN=42`、`CONFIG_ESP32S3_UART0_RXPIN=40`。

### 3.6 编译

```bash
export PYTHONPATH=<openvela>/prebuilts/tools/python/dist-packages/kconfiglib
export PATH=<openvela>/prebuilts/gcc/linux-x86_64/xtensa-esp32s3-elf/bin:$PATH

cd nuttx
make olddefconfig
make -j8
```

产物：`nuttx/nuttx.bin`。首次编译约 15~30 分钟。

**仓库里带的编译脚本**（`firmware/build/`）是当时在开发机上用的，路径写死，
需要按自己的目录改 `PYTHONPATH` / `PATH` / 工作目录后再用：

| 脚本 | 用途 |
|------|------|
| `build68.sh` | 常规重编（清掉我们模块的 `.o` 强制重编） |
| `build70_v1.3.0.sh` | V1.3.0 那次（额外清掉 `ota*.o`、`ai_voice*.o`、`voice_service*.o`、`app_main*.o`） |

脚本里的关键一行：

```bash
make -j8 USE_NXTMPDIR_ESP_REPO_DIRECTLY=y NXTMPDIR=<openvela>/nxtmpdir
```

### 3.7 烧录

同"路径 A"的命令，把 bin 换成新编出来的 `nuttx/nuttx.bin` 即可：

```bash
python -m esptool --chip esp32s3 --port COM3 --baud 921600 \
  --before default-reset --after hard-reset write-flash \
  --flash-mode dio --flash-freq 80m --flash-size 16MB \
  0x8000  ../firmware/partition/partition-table-2mb-ab.bin \
  0x10000 nuttx/nuttx.bin
```

## 四、上电后的配置

### 4.1 配网（屏幕操作）

首页 → **网络设置** 页 → 扫描 → 选 SSID → 输入密码 → 连接。

> 板卡**只支持 2.4G Wi-Fi**，5G 频段连不上。

### 4.2 服务器地址

配置持久化在 SD 卡 `/mnt/sd/plant.cfg`，重启自动恢复：

```
# /mnt/sd/plant.cfg   每行 key=value，# 开头是注释
wifi_ssid=YourSSID
wifi_password=YourPassword
server_host=<你的服务器IP>
server_port=8011
```

换环境时在屏幕上重新扫描选网即可，不用手工改这个文件。

> 板卡取 OTA 包也是用配置里的 `server_host`，
> 所以"让板卡 OTA 指向哪台服务器"就是改这里的地址。

串口（115200）进 NSH 后，命令入口是 **`plant`**：


## 六、常见问题

| 现象 | 原因 / 处理 |
|------|-----------|
| 点屏幕卡住、扫描网络半天不出结果 | 上位机开着串口却不读数据把板卡输出阻塞了。关掉串口工具，或确保持续读取。本版已做限时等待 200 ms 缓解 |
| 一打开串口板卡就重启 | Python 的 pyserial 默认 DTR/RTS=1，正好是 ESP32-S3 USB-Serial-JTAG 的复位组合。置低后再 open |
| 编译报找不到 kconfiglib | `PYTHONPATH` 没指向 openvela 的 prebuilts |
| 编出来的固件起不来 | 确认烧的是 `0x10000`；确认没有 `erase_flash` |
| **`plant ota check` 显示升级成功，重启后版本没变** | **分区表没烧对**：固件按 `ota_1 @0x210000 / 2MB` 写镜像，引导程序却按 flash 里的旧表去 `0x610000` 找。修法：烧 `0x8000 firmware/partition/partition-table-2mb-ab.bin`。取证步骤见 `firmware/apps/plant-companion/docs/PARTITION_TABLE_HANDOVER.md` |
| 想确认板上分区表是哪一版 | `esptool read-flash 0x8000 0xc00 pt.bin` 后跑 `python firmware/partition/make_partition_table.py --dump pt.bin 0`，看 `ota_1` 的 offset 是 `0x210000`（对）还是 `0x610000`（旧） |
| 升级过程中板卡串口写超时 / 心跳中断 | 两条升级路径并发（UI 停在升级页 + 串口再敲 `plant ota check/stage`）。等一边跑完；卡死了用 `esptool flash-id` 复位救回 |
| 传感器读数是 0 / 乱码 | 进过拍照页后没等轮询恢复；或 GPIO42/40 被摄像头占着。跑 `plant soil scan` 排查 |
| 换网后连不上服务器 | 屏幕重新配网；心跳会在 1 分钟内自愈补注册 |
