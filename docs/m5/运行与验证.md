# M5 运行与验证

## 准备 SDK

使用 Linux、ESP32-S3 Xtensa 工具链和 openvela 工作区。SDK 的 `apps` 和 `nuttx` 各自固定到 [基线清单](../../patches/m5/baselines.json) 的提交。该清单记录的是历史构建树使用的两个仓库 HEAD；额外的板级、UART、相机与 UI 文件由 overlay 提供。准备工作区时还需匹配 SDK 的其余项目和 Espressif 依赖。

安装 Python、kconfig 工具、curl、unzip 与 make。将 LVGL v9.2.1 压缩包按清单校验后解压，将目录放到 SDK 的 `apps/graphics/lvgl/lvgl`。必须在应用 overlay 前准备完整的 LVGL 源树，overlay 只携带两个 NuttX 适配文件。网络受限时可按清单预置其余依赖压缩包。

公开提交包含相关源码。预编译库、模型数据、录音夹具与生成字库单独列在清单的 `external_build_inputs` 中，评审或复现时需要从获授权的来源另行取得，按清单的相对路径和 SHA-256 放到资产目录。历史隔离构建使用了这些配套文件。

在比赛仓根目录校验源码包并将 overlay 写入专供 M5 的干净 SDK。M5 应用在比赛仓叫 `app/plant-companion-m5`，构建时放在 SDK 的 `apps/plant-companion`。

```bash
python3 tools/m5/prepare.py
python3 tools/m5/prepare.py /path/to/m5-sdk --assets /path/to/authorized-m5-assets --apply
cd /path/to/m5-sdk/nuttx
./tools/configure.sh m5stack-cores3:contest_v672
make olddefconfig
make -j8
python3 ../apps/plant-companion/tools/check_boot_heap.py .
```

历史 VM 构建使用已配置的 Espressif 缓存，另加 `USE_NXTMPDIR_ESP_REPO_DIRECTLY=y` 和指向该缓存的 `NXTMPDIR`。生成的 `apps/Kconfig` 包含本机路径，由构建环境重新生成。

设备运行需自行配网并配置自己的服务地址、设备注册和绑定。审阅源码清除了工厂 Wi‑Fi 和服务默认值，OTA 与诊断地址使用文档保留地址。实际设备仍运行原镜像。参考 [CoreS3 板级分区表](../../patches/m5/sdk-overlay/nuttx/boards/xtensa/esp32s3/m5stack-cores3/configs/openvela/partition_table.csv)，烧录前先核对目标板分区与镜像尺寸。

## 已有证据

| 项目 | 结果 |
| --- | --- |
| 历史 1.3.672 镜像 | 4,794,688 字节，SHA-256 为 `277f778cbe30edeef159fc6a5c99a94c5b5308b4edc52d5cc8afa93c2381fcc0` |
| 实机回退 | 整镜像读回一致，68 字节上下文缓冲和 16 项启动自检通过 |
| 回正 | 实际编码器从偏航 465、俯仰 727 到 465、686，目标为 460、684 |
| 真机演示 | 语音唤醒、问答、10 个方向探索、语音进入待机均完成。植物状态语音切页超时后用页面命令切换 |
| 底座稳定性 | 历史同版另有间歇串口反馈丢失；单次回正与单次探索成功的范围分别记录 |
| 本次源码审阅包 | 71 个归档构建输入逐项核对，公开配置修改前后哈希分别记录。清单以外的配套源来自现存 SDK。隔离 SDK 已完成构建，重编镜像未烧录 |

隔离构建使用两份干净 SDK 克隆和校验过的本地依赖缓存。重编镜像为 4,794,640 字节，启动堆 20,272 字节，ELF 中核对了 `setjmp`、`longjmp` 与底座事务符号。链接器报告 RWX 段警告。详见 [构建结果](公开构建结果.json)。设备上的历史镜像与这次清理配置后重编的镜像哈希不同。

## 发布前检查

- SDK 公共仓改动单独按官方流程 fork 后向对应公共仓提 PR。这里保留的 overlay 用于审阅与本地复现。
- 核对预编译语音、JPEG、VAD 库、相机色彩转换对象和字库的来源及再分发条件；保留随源码的许可与来源文件。
- 确认重编镜像的设备启动与 OTA 布局，再补做公开配置的真机验证。
- 审阅 AI Coding 摘录和身份字段，按官方日志工具核验后决定正式日志归档方式。
- 将根 README 加上 M5 独立入口，保留现有 BOX 和无线节点映射。先更新 fork，再向比赛分支发 PR。
