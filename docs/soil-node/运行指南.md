# 无线土壤节点运行指南

## 1. 硬件

| 项目 | 值 |
| --- | --- |
| 主控 | ESP32-WROOM-32E，目标板 esp32-devkitc |
| Flash | 4 MB，DIO，40 MHz |
| RS485 接口 | 板上标记端口 1，UART1，`/dev/ttyS1` |
| 引脚 | RX GPIO19，TX GPIO18，DE GPIO5，高电平发送 |
| 探头 | Modbus RTU，9600 8N1，地址 2，寄存器 0 起读 8 个 |
| LittleFS | 偏移 `0x180000`，长度 `0x80000` |
| 控制台 | CH340 串口，115200；COM11 仅为开发电脑当时的端口名 |

RS485 A 接探头 A、B 接 B，按实际传感器供电要求供电并共地。该节点与 ESP32-S3-Box 主机是不同硬件，不要使用主机固件、引脚表或烧录地址。

## 2. 拉取与构建

Linux 环境中建立独立土壤节点工作区。使用比赛仓 manifest：

```bash
repo init -u https://github.com/open-vela/contest2026_053_yelvtizhineng \
  -b dev-ai-contest-2026 -m soil-node.xml
repo sync -c -j8
```

**以上命令以本次更新已合入比赛仓为前提；合入前请检出对应 PR 分支。** 检查本地版本时，应将本仓放在工作区 `contest2026_053_yelvtizhineng/`，再运行下面的准备脚本。应用和板配置由 manifest 映射；脚本也能在缺少映射时建立相同链接，已有冲突目录会拒绝覆盖。

准备 ESP32 HAL 基础源码及其子模块，版本为 `9fc713a95b1ff150dd0b0647e465d3c624056bb1`。已验证构建机将其保存在 `cache/esp-hal-3rdparty`。用 `--esp-hal` 指向这份**独立工作区内**的 HAL，不能指向另一套正在使用的工程。

若独立工作区还没有 HAL 缓存，在工作区根目录执行：

```bash
mkdir -p cache
git clone https://github.com/espressif/esp-hal-3rdparty.git cache/esp-hal-3rdparty
git -C cache/esp-hal-3rdparty checkout 9fc713a95b1ff150dd0b0647e465d3c624056bb1
git -C cache/esp-hal-3rdparty submodule update --init --depth 1 \
  components/mbedtls/mbedtls components/esp_phy/lib components/esp_wifi/lib \
  components/bt/controller/lib_esp32 components/esp_coex/lib
```

`soil-node.xml` 另外将 MQTT-C 指向上游 `LiamBindle/MQTT-C` 的 1.1.5 标签。本次核对该版本四个核心源码/头文件与构建机所用内容一致，避免随通用 manifest 的依赖分支漂移。已有 MQTT-C 缓存目录时，应确保其时间戳不早于下载包，或在干净工作区由 repo 管理该目录，避免重复解压嵌套。

```bash
python3 contest2026_053_yelvtizhineng/tools/soil-node/prepare.py . \
  --esp-hal ./cache/esp-hal-3rdparty --check
python3 contest2026_053_yelvtizhineng/tools/soil-node/prepare.py . \
  --esp-hal ./cache/esp-hal-3rdparty --apply
```

脚本先核对补丁涉及文件的 SHA256，再备份并应用 NuttX/apps/HAL 的本地补丁，建立映射、安装完整配置；不下载 SDK、不创建云端凭据。不适配的文件将拒绝修改。公共仓补丁还需按比赛流程另提 PR，见 [补丁说明](../../patches/soil-node/README.md)。

完整配置位于 `board/soil-node/configs/soilnode/defconfig`，取自已构建固件的 `.config`，包含 MQTT/TLS、NTP 和 LittleFS 选项，替代早期不完整的精简配置。已验证工具链是 `xtensa-esp32-elf-gcc 8.4.0`（esp-2020r3），需要 make、Python kconfiglib 和 SDK 构建依赖。

标准 openvela 工程统一入口为：

```bash
./build.sh esp32-devkitc:soilnode -j8
```

独立 NuttX 工程或复用已经准备好的 HAL 缓存时，可使用实际验证环境的 Make 方式。先确保交叉工具链、kconfiglib 已加入 PATH/PYTHONPATH：

```bash
cd nuttx
USE_NXTMPDIR_ESP_REPO_DIRECTLY=y NXTMPDIR="$(cd ../cache && pwd)" make -j8
```

构建产物为 `nuttx/nuttx.bin`。当前测试记录会明确区分原工程构建、本次整理版本的独立目录构建与从网络全新 repo sync 构建，不混用结论。不要对现场工程运行 distclean，以免清掉配置或 HAL 缓存。

## 3. 烧录

先关闭占用串口的软件，将 `<PORT>` 换成实际 CH340 端口：

```bash
python -m esptool --chip esp32 --port <PORT> --baud 460800 \
  write-flash --flash-mode dio --flash-freq 40m --flash-size 4MB \
  0x1000 nuttx/nuttx.bin
```

普通升级只写 `0x1000`（4 KiB），保留 LittleFS。不要全片擦除，也不要把该固件写到 `0x0`。本增量不提供含 Wi-Fi/MQTT 凭据的完整 Flash 镜像。空白板还需要具备相应引导和有效云端凭据。

## 4. 配网与验证

1. 初次使用或联网失败时连接无密码热点 `ZXB-Soil-<MAC后六位>`，配网窗口最长 15 分钟。
2. 手机选择继续使用该网络，明确访问 `http://192.168.4.1/`，使用 HTTP。
3. 填写 2.4 GHz Wi-Fi、探头地址/波特率、上报周期及校准参数，点击验证并保存。
4. 已配置节点可留空 MQTT 用户名和密码以保留原凭据；新板必须另行准备有效凭据。
5. 默认 60 秒上报一次并启用省电。串口应有 `WIFI_CONNECTED`、`SOIL_OK`、`TLS_READY`、`MQTT_PUBLISH=OK`、`DEEP_SLEEP_US`；云端核对实际遥测时间和八参数。

NSH 可执行 `soil_node sample`、`soil_node sample 2 9600`、`soil_node report-once`、`soil_node mqtt-test`、`soil_node portal`。自动任务采集期间避免并发手动采样。省电关闭时的长期运行存在 TLS 资源释放限制，见提交检查。
